# CLAUDE.md — Instructions for Claude Code

This file tells you everything you need to know about this codebase, how it is structured, and how to work on it effectively. Read this before touching any file.

---

## What this project is

An AI-powered pipeline that produces short-form vertical videos (9:16, under 2 minutes) on finance and AI topics. The user controls every step via a Streamlit wizard. Each pipeline step must be approved before the next runs.

The full pipeline is: gather data → fact-check → write script → generate background → source images → assemble video → download.

---

## Architecture rules — never break these

**One function per module.** Every file in `pipeline/` exposes a single `run(state: dict) -> dict` function. It receives the full session state, does its work, and returns an updated state dict. Nothing else is exported from pipeline modules.

**State is the contract.** All data flows through `st.session_state` using the schema defined in `utils/state.py`. Never pass data between pipeline steps any other way. Never add new keys to session state without first adding them to the schema in `state.py`.

**Skills are injected at runtime.** The markdown files in `skills/` are read from disk and injected as system prompts into Claude API calls. Never hardcode prompt instructions directly in Python. If you need to change how Claude behaves in a step, edit the relevant skill file.

**Steps are sequentially locked.** A step cannot run until `state.stepN_approved` is `True` for the previous step. This is enforced in `app.py`. Do not bypass this in any pipeline module.

**No raw tracebacks to the user.** Every API call must be wrapped in a try-except. On failure, surface an `st.error` with a plain-English message and a Retry button. Never let a Python exception reach the Streamlit UI unhandled.

## Session state schema

Always refer to `utils/state.py` for the canonical schema. Key fields:

```python
state = {
    # Step flags
    "step1_approved": False,
    "step2_approved": False,
    "step3_approved": False,
    "step4_approved": False,
    "step5_approved": False,
    "step6_approved": False,

    # Step 1
    "topic_mode": None,           # "live_news" | "custom_topic" | "mode_3"
    "custom_topic": "",
    "raw_data": None,             # list of article dicts or research string

    # Step 2
    "cleaned_data": None,         # string — fact-checked and user-edited
    "factcheck_flags": [],        # list of {claim, confidence, note}

    # Step 3
    "script": None,               # final approved script string
    "word_count": 0,
    "estimated_duration_s": 0,

    # Step 4
    "visual_style": None,         # "cinematic" | "clean" | "vintage" | "dynamic"
    "background_video_path": None,

    # Step 5
    "overlay_sequence": [],       # list of image paths in script order

    # Step 6
    "final_video_path": None,
}
```

## API clients

All clients are initialised once in `utils/api_clients.py` and imported from there. Never initialise a client inside a pipeline module or a Streamlit callback.

```python
from utils.api_clients import claude, elevenlabs, openai_client, pexels, marketaux, finnhub
```

Keys are loaded from `st.secrets` (production) or `.env` (local dev). The `.env` file is gitignored.

## Claude API calls

Always use `claude-sonnet-4-5` as the model. Always inject the relevant skill file as the system prompt. Parse responses defensively — if you expect JSON, wrap the parse in a try-except and retry with a repair prompt on failure.

```python
skill = Path("skills/script_skill.md").read_text()

response = claude.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=2000,
    system=skill,
    messages=[{"role": "user", "content": cleaned_data}]
)

script = response.content[0].text
```

## News APIs (Step 1 Mode A)

Use Marketaux as the primary source. Filter to the last 24 hours. If Marketaux returns fewer than 3 articles or hits its daily cap (HTTP 429), fall back to Finnhub market news automatically. Do not surface this fallback to the user — just log it.

```python
# Marketaux
GET https://api.marketaux.com/v1/news/all
    ?filter_entities=true
    &language=en
    &published_after={yesterday_iso}
    &api_token={MARKETAUX_API_KEY}

# Finnhub fallback
GET https://finnhub.io/api/v1/news
    ?category=general
    &token={FINNHUB_API_KEY}
```

## Pexels image search (Step 5)

Search with a short, specific query generated by Claude from the script segment (not the raw segment text). Download images to a temp directory before use — do not hotlink. Use `orientation=landscape` for most finance topics. Return 4 candidates per segment.

```python
GET https://api.pexels.com/v1/search
    ?query={claude_generated_query}
    &per_page=4
    &orientation=landscape
Authorization: {PEXELS_API_KEY}
```

## Video assembly rules

The composition rules are defined in `skills/composition_skill.md`. Always read that file before writing any compositing code. The key constraints are:

- Canvas: 1080 x 1920 px
- Overlay images: max 85% canvas width (918 px), rounded corners 24 px, drop shadow
- Bottom 200 px: reserved for captions, keep overlays out of this zone
- Fade in: 0.4 seconds. Fade out: 0.3 seconds
- Each overlay: minimum 4 seconds, maximum 18 seconds on screen
- Background: Ken Burns loop must match or exceed total audio duration

Always use `libx264` with `crf=23` and `-movflags faststart` for the FFmpeg output.

## Streamlit conventions

**State initialisation.** Always initialise state at the top of `app.py` in a single block using the schema from `utils/state.py`. Use `st.session_state.setdefault()` so reruns do not wipe existing values.

**Step locking.** Render locked steps as `st.container()` with `st.markdown('<div class="step-locked">', unsafe_allow_html=True)`. Never render interactive widgets inside a locked step.

**Long-running tasks.** ElevenLabs generation and video render must run in background threads. Use `threading.Thread` with a shared `state` dict for progress. Poll with `st.rerun()` every 2 seconds while running.

**UI components.** Use the wrappers in `utils/ui_components.py` rather than inline Streamlit calls for step cards, image cards, approval bars, and word count editors. If a component does not exist yet, add it to `ui_components.py` before using it.

**CSS.** All style overrides live in `.streamlit/custom_style.css`, injected at startup via:

```python
css = Path(".streamlit/custom_style.css").read_text()
st.markdown(f"<style>{css}</style>", unsafe_allow_html=True)
```

Never write inline CSS anywhere else.

## File naming and output paths

Temporary files go in `tmp/`. Final outputs go in `outputs/`. Both directories are gitignored.

Final video file naming convention:

```
outputs/{topic-slug}-{YYYYMMDD}.mp4
```

Generate the slug from the topic string: lowercase, spaces to hyphens, max 40 characters, strip special characters.

## Error handling pattern

Every API call follows this pattern:

```python
MAX_RETRIES = 2

for attempt in range(MAX_RETRIES + 1):
    try:
        result = some_api_call()
        break
    except SomeAPIError as e:
        if attempt == MAX_RETRIES:
            st.error(f"Could not complete this step: {e}. Use the Retry button to try again.")
            st.stop()
        time.sleep(2 ** attempt)  # exponential backoff
```

## What not to do

- Do not add new pipeline steps without updating the state schema and the step lock logic in `app.py`
- Do not call `st.rerun()` inside a pipeline module — only call it from `app.py` callbacks
- Do not hardcode any API key anywhere in the codebase
- Do not commit any file in `tmp/`, `outputs/`, or `.streamlit/secrets.toml`
- Do not use `st.experimental_*` APIs — use only stable Streamlit APIs
- Do not skip the approval checkpoint between steps even for testing — use the mock state helper in `tests/helpers.py` instead
- Do not write a pipeline module that does more than one thing — split it into utils functions if it is getting complex

## Testing approach

Each pipeline module has a corresponding test in `tests/`. Tests use mock API responses from `tests/fixtures/`. Never hit a live API in a test.

To test a specific pipeline step in isolation without running the full Streamlit app:

```python
from tests.helpers import mock_state
from pipeline.script import run

state = mock_state(up_to_step=2)  # pre-approves steps 1 and 2
result = run(state)
assert result["script"] is not None
assert 150 <= result["word_count"] <= 320
```

## Common tasks

**Add a new visual style to the Ken Burns background:**
1. Add the style name and DALL-E prompt template to `utils/styles.py`
2. Add the option to the `st.radio` in `app.py` Step 4 section
3. Test with `pipeline/background.py` directly using `python -c "from pipeline.background import run; ..."`

**Change the ElevenLabs voice:**
Update `ELEVENLABS_VOICE_ID` in `.streamlit/secrets.toml`. No code changes needed.

**Adjust script length target:**
Edit `skills/script_skill.md`. Change the word count target and the beat timing. Re-test Step 3.

**Add a new topic mode:**
1. Add the mode key to the `topic_mode` enum in `utils/state.py`
2. Add a branch in `pipeline/gather.py`
3. Add the UI option to the `st.radio` in `app.py` Step 1 section
4. Add a test fixture in `tests/fixtures/`
